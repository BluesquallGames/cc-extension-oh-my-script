# 模块热更

OMS 会在编辑器里监听脚本和配置变化。保存文件后，它会重新构建受影响的脚本，并让场景使用新的代码。

## 什么时候会刷新

这些变化会触发刷新：

- 修改 `src` 里的项目脚本。
- 修改扩展 `oms/src` 里的脚本。
- 新增或删除 `*.component.ts`。
- 修改 `oms.config.*`。
- 启用或禁用项目内扩展。

## 用户能感知到什么

通常表现为：

- 控制台出现 OMS 构建日志。
- 场景脚本重新执行。
- 新增的组件类可以被 Creator 识别。
- `oms://` 导出的内容更新。
- TypeScript 声明跟随扩展导出变化。

## 写热更友好的代码

推荐：

- 把一次性注册逻辑放在入口脚本里。
- 把需要挂到节点上的逻辑写成组件脚本。
- 让模块导出函数、类或配置，减少 import 时立即执行大量副作用。
- 修改全局状态时，给重复执行留出余地。

## 常见问题

### 保存后没有变化

可以按这个顺序检查：

1. 文件是否在 OMS 源码目录里，比如项目 `src` 或扩展 `oms/src`。
2. 组件文件名是否包含 `.component`。
3. 控制台是否有构建错误。
4. 修改依赖安装状态后，是否需要重启扩展或编辑器。

### 组件引用丢失

优先检查 `oms/uuids.json` 是否存在、是否被覆盖、是否有冲突。组件脚本的 UUID 稳定性依赖这个文件或源码里的 Inline UUID。
